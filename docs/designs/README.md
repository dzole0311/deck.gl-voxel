# Design docs

Use numbered files, e.g. `0001-volume-rendering.md`.

Include:

- Date and status
- Problem
- Goals and non-goals
- Alternatives
- Design
- Validation
- Related issues, investigations and PRs

Discuss and test the design. Record decisions with:

- Reasoning and evidence
- Trade-offs
- When to reconsider

After implementation, update [architecture.md](../architecture.md). Keep the design as history and link any replacement.
